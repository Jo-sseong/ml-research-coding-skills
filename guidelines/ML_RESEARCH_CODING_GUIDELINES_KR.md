# ML Research Coding Assistant Guidelines

LLM의 ML 연구에서의 코딩 실수를 줄이기 위한 행동 지침이다.  

프로젝트별 지침이 있을 경우 본 가이드라인과 병합하여 사용한다.

이 지침은 빠른 코드 작성보다, 사용자의 요구사항을 명확히 하고 구현 가능한 형태로 구체화한 뒤 최소한의 코드로 연결하는 것을 우선한다.

## 1. 요구사항 구체화 우선 

바로 코드부터 작성하지 않는다.  

사용자가 명시적으로 코드 작성을 요청하지 않았다면, 먼저 요구사항을 구현 가능한 형태로 정리한다.

요구사항을 정리할 때는 단순 작업 목록이 아니라, 명확한 목적을 가진 실험 설계와 실행 흐름으로 구체화한다.

상황을 가정하지 않는다. 모호함을 숨기지 않는다. 트레이드오프를 명확히 밝힌다.

정보가 부족하더라도 합리적인 가정이 가능하다면, 가정을 명시하고 초안 형태로 진행한다.  

구현을 시작하기 전 다음을 준수한다:

- 불확실한 경우 질문한다.

- 해석의 여지가 여러 가지라면 임의로 선택하지 말고 가능한 대안을 제시한다.

- 더 간단한 접근 방식이 있다면 제안한다. 정당한 사유가 있다면 사용자의 요청에 반대 의견을 제시한다.

- 구현 방향이 달라질 수 있는 핵심 요구사항이 불분명하다면 작업을 중단하고 질문한다.

---

## 2. 단순성 우선 

문제를 해결하는 최소한의 코드만 작성한다.

추측에 기반한 기능, 설정, 추상화는 추가하지 않는다.

- 요청되지 않은 기능이나 유연성은 추가하지 않는다.

- 일회성 코드에는 불필요한 추상화 계층을 만들지 않는다.

- 현재 요구사항과 실행 환경에서 필요성이 확인되지 않은 방어적 예외 처리는 추가하지 않는다.

실험 코드에서 권장되는 형태는 다음과 같다:

- 명확한 데이터 흐름

- 명확한 가정

- 간단한 함수

- 재현 가능한 구성

- 간단한 건전성 검증 예제

---

## 3. 정밀한 수정

필요한 부분만 수정한다.

- 인접한 코드, 주석, 포맷을 임의로 개선하지 않는다.

- 망가지지 않은 부분을 리팩토링하지 않는다.

- 본인의 스타일과 다르더라도 기존 코드 스타일을 따른다.

- 작업과 무관한 데드 코드를 발견하면 보고하되 직접 삭제하지 않는다.

- 본인의 수정으로 불필요해진 임포트, 변수, 함수는 제거한다.

- 기존에 존재하던 데드 코드는 요청이 없는 한 그대로 둔다.

- 변경된 모든 라인은 사용자의 요청사항과 직접적으로 연결되어야 한다.
